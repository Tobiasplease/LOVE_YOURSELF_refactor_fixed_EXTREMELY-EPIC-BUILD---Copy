⏺ Great question! Looking at the code, there's actually redundant functionality. Here are
  the key differences:

  convert_gcode_to_servo_format (in standalone_svg_converter.py):

  - Purpose: Convert vpype-generated G-code to servo format
  - Logic: G0 commands → pen up, G1 commands → pen down
  - Adds: Complete header/footer with origin offset
  - Input: Clean vpype G-code (no Z commands)

  convert_z_to_servo (in bcnc_utils.py):

  - Purpose: Convert Z-axis commands to servo commands
  - Logic: Looks for actual Z-axis movements (Z > 0 = up, Z ≤ 0 = down)
  - Modifies: Existing G-code by replacing Z commands
  - Input: G-code that might have Z-axis commands

  The Issue:

  You're running BOTH functions on the same file, which is redundant! Looking at lines
  404-409, the script:

  1. Uses convert_gcode_to_servo_format() to create servo G-code from vpype output
  2. Then runs convert_z_to_servo() on the already-converted file

  This is unnecessary because:
  - vpype doesn't generate Z commands (it uses G0/G1 for pen up/down)
  - convert_gcode_to_servo_format() already handles the conversion properly
